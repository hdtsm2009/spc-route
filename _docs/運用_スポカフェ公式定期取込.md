# 運用手順：スポカフェ公式エクスポートの定期取込

スポカフェ管理画面から新しい公式エクスポート（番地付き・ステータス列あり）が出たら、これを取り込んで
`api/stores.json` を更新・デプロイする手順。**POI店名検索は使わない**（番地があるため）。

## 1. 取り込み（ファイルを置くだけ）
新エクスポートを **`_マスタデータ/スポカフェ公式エクスポート_<YYYYMMDD>.csv`** という名前で置く。
（各スクリプトは `スポカフェ公式エクスポート_*.csv` の**最新（名前順で末尾）を自動選択**する。日付名にしておけば最新が選ばれる）

> 生CSVは個別店舗データを含むので `_マスタデータ`（git管理外）に置く。取込メタ（件数・SHA256）は
> `_docs/取込メタ_スポカフェ公式_<日付>.md` に1枚足しておくと再現性が残る。

## 2. パイプライン一括実行
```powershell
cd "G:\マイドライブ\作業フォルダ2025～\Claude作業フォルダ\Claudecode スポカフェ\訪問店舗提案サービス"

# 検証＋フェーズ06 dry-run まで（v2は書き換えない）
python _scripts/パイプライン全実行.py

#  _output/_phase06_移行レポート.csv を確認（勢い/閉店/誤検出の引継ぎ件数が妥当か）
#  問題なければ本適用＋stores.json再生成
python _scripts/パイプライン全実行.py --apply
```

個別に回す場合の順番は README「現行パイプライン」を参照（0a→1→1b→2→3→4→5→6→7）。

## 3. 確認（最低限）
- preflight出力：ステータス別件数（掲載が基準）／電話衝突（`_検証_電話衝突.csv`）。
- `_新04_取込サマリ.txt`：`掲載 = scrapeマッチ + 新規追加 + 座標失敗` が閉じているか。
- 最終 v2 で **POI/補完(POI) 由来ソースが0件**。
- `_検証_GSI失敗_要手当て.csv`：座標が取れない店（多くは海外＝対象外）。国内で住所不備のものだけ手当て。
- ローカルで主要エリアの候補が番地付きで出るか（`api/` の関数を直接叩くか、デプロイ後にライブ確認）。

## 4. デプロイ
```powershell
git add api/ _data/store_id_map.json _docs/取込メタ_*.md
git commit -m "スポカフェ掲載店データを公式エクスポート(YYYYMMDD)に更新"
git push        # Vercel自動デプロイ
```
更新履歴（`public/index.html` の `<ul class="changelog">` 先頭）に1行追記するのを忘れずに。

## 注意（やってはいけないこと）
- **`_scripts/_archive/フェーズ07_スポカフェ座標GSI上書き.py` は実行しない**（旧POI座標の暫定上書き。現行は不要）。
- 04b / 04c（POI店名検索）も実行しない（04cはフェーズ06がenrichキャッシュのキー再生成に流用するため残置しているだけ）。
- 本番（main）へは dry-run の移行レポートを確認してから反映する。
